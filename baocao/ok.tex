\section*{LỜI MỞ ĐẦU}
\addcontentsline{toc}{section}{LỜI MỞ ĐẦU}

\paragraph*{1. Lý do chọn đề tài}
Trong hệ sinh thái phát triển ứng dụng web đương đại, thư viện React đã giữ vững vai trò thống trị giao diện người dùng suốt hơn một thập kỷ. Tuy nhiên, kiến trúc Single Page Application (SPA) truyền thống dựa trên cơ chế Client-Side Rendering (CSR) đã bộc lộ những nhược điểm cố hữu: kích thước gói mã nguồn Javascript tải về trình duyệt quá lớn, điểm hiệu năng FCP và LCP bị ảnh hưởng tiêu cực, khả năng tối ưu hóa công cụ tìm kiếm (SEO) bị hạn chế nghiêm trọng do bot tìm kiếm chỉ đọc được tài liệu HTML rỗng, và nguy cơ mất an toàn bảo mật khi để lộ các khóa API phía máy khách.

Sự ra đời của công nghệ Next.js [1] với kiến trúc App Router kết hợp cùng React 19 [2] đã tạo ra bước nhảy vọt quan trọng. Bằng cách chuyển dịch trọng tâm kết xuất về phía máy chủ (Server-Driven UI), Next.js cung cấp giải pháp triệt để cho bài toán SEO, tối ưu tốc độ nạp trang đầu thông qua Streaming với React Suspense và cơ chế Caching đa tầng Incremental Static Regeneration (ISR).

Thực hiện đúng định hướng của môn học Các Công nghệ Lập trình Hiện đại: \textit{``Trọng tâm của môn học là làm chủ CÔNG NGHỆ, không phải sa đà vào nghiệp vụ phức tạp; ứng dụng xây dựng chỉ là phương tiện để áp dụng và minh họa''}, nhóm sinh viên chúng em lựa chọn đề tài: \textbf{``Tìm hiểu công nghệ Next.js qua Ứng dụng Tra cứu \& Khám phá Phim ảnh MovieHub''}. Nhóm sử dụng nguồn dữ liệu mở chất lượng cao từ The Movie Database (TMDB) REST API v3 [3] làm nền tảng backend có sẵn, giúp nhóm dồn toàn bộ nguồn lực để làm chủ các cơ chế cốt lõi của Next.js.

\paragraph*{2. Mục tiêu nghiên cứu theo chuẩn đánh giá 3 tầng}
Đồ án được thiết kế nhằm chứng minh năng lực làm chủ công nghệ của nhóm theo 3 tầng chuẩn mực:
\begin{itemize}[noitemsep]
    \item \textbf{Tầng 1A (Bắt buộc lõi):} Hiểu rõ cấu trúc App Router, phân biệt tường minh ranh giới giữa Server Component (mặc định) và Client Component (\texttt{"use client"}), thực hiện lấy dữ liệu phía server an toàn và nắm vững toàn bộ luồng kết xuất (Render Pipeline).
    \item \textbf{Tầng 1B (Lõi tự chọn theo ứng dụng):} Làm chủ Dynamic Routing (\texttt{/movie/[id]}), Streaming song song với React Suspense, Caching dữ liệu tĩnh có thời hạn (ISR), tối ưu hóa hình ảnh với \texttt{next/image}, Dynamic SEO Metadata (\texttt{generateMetadata}), và Server Actions (\texttt{"use server"}) thao tác Cookie an toàn.
    \item \textbf{Tầng 2 (Chuẩn kỹ nghệ phần mềm):} Quản lý phiên bản mã nguồn với Git Flow, phân nhánh tính năng độc lập, Pull Request có review chéo, thiết lập CI tự động với GitHub Actions, và phát triển bộ kiểm thử tự động với Vitest [6] đạt 100\% pass.
    \item \textbf{Tầng 3 (Đào sâu nâng cao và đo lường):} Đo lường Core Web Vitals (LCP, CLS, FCP) bằng Google Lighthouse [4], phân tích bundle JS với \texttt{@next/bundle-analyzer}, và thực nghiệm đối chứng thời gian phản hồi của cơ chế Streaming Suspense.
\end{itemize}

\paragraph*{3. Phạm vi nghiên cứu và phân công nhiệm vụ}
Khung thời gian thực hiện đồ án được rút gọn xuống \textbf{7 tuần} theo chỉ đạo của giảng viên hướng dẫn ThS. Phạm Thi Vương. Khối lượng công việc được phân chia cân bằng, minh bạch (33.3\% mỗi thành viên): Nguyễn Công Quân (Trưởng nhóm -- Kiến trúc Base, Trang chủ, Caching ISR, Tối ưu ảnh, Web Vitals), Nguyễn Quốc Đại (Dynamic Route, Streaming Suspense, Xử lý ngoại lệ, Dynamic SEO, Vitest), Nguyễn Thái Vinh (Tìm kiếm Debounce, Server Actions lưu Cookie, GitHub Actions CI, Bundle Analyzer).

\paragraph*{4. Kế hoạch và tiến độ thực hiện tổng quát (7 tuần)}
Tiến độ thực hiện 7 tuần của nhóm được tóm tắt chi tiết trong Bảng 1 bên dưới (được trình bày ở đầu Chương 2).

\section{TỔNG QUAN VÀ PHÂN TÍCH BẢN CHẤT CÔNG NGHỆ NEXT.JS}

\subsection{Lịch sử và bối cảnh phát triển của Next.js}
Next.js được phát triển bởi Guillermo Rauch và đội ngũ kỹ sư tại Vercel, ra mắt lần đầu tiên vào năm 2016 như một giải pháp đơn giản hóa việc Server-Side Rendering (SSR) cho các ứng dụng React [1]. Quá trình tiến hóa của Next.js trải qua 3 giai đoạn mang tính bước ngoặt:
\begin{enumerate}[noitemsep]
    \item \textbf{Giai đoạn React SPA truyền thống (trước 2016):} React vận hành hoàn toàn ở phía client (CSR). Trình duyệt tải về tệp HTML rỗng cùng gói Javascript lớn, khiến thời gian hiển thị nội dung ban đầu (FCP/LCP) bị chậm và bot tìm kiếm không cào được nội dung đầy đủ.
    \item \textbf{Giai đoạn Pages Router (Next.js 1 -- 12):} Giới thiệu cơ chế định tuyến theo cấu trúc tệp tin trong thư mục \texttt{pages/}. Cung cấp các hàm tiền kết xuất như \texttt{getServerSideProps} và \texttt{getStaticProps}. Mặc dù cải thiện vượt bậc về SEO, mô hình này vẫn gửi toàn bộ mã nguồn của trang xuống client để hydrate, gây lãng phí băng thông.
    \item \textbf{Kỷ nguyên App Router và React Server Components (Next.js 13 -- 16):} Tái kiến trúc toàn diện dựa trên nền tảng React 19 [2] và kiến trúc Server-Driven UI [7]. Mô hình \textbf{React Server Components (RSC)} cho phép các component thực thi 100\% trên máy chủ, truyền dữ liệu theo luồng (Streaming), kết hợp với \textbf{Server Actions} tạo nên một nền tảng fullstack hoàn chỉnh.
\end{enumerate}

\subsection{Kiến trúc và các cơ chế cốt lõi của Next.js App Router}

\subsubsection{React Server Components (RSC) và cơ chế RSC Payload}
Trong kiến trúc App Router, mặc định mọi component đặt trong thư mục \texttt{app/} đều là Server Component. Khi client gửi một yêu cầu truy cập, máy chủ Next.js thực thi mã logic, gọi dữ liệu từ TMDB API [3], và kết xuất component thành một luồng dữ liệu định dạng đặc biệt gọi là \textbf{RSC Payload} (chuỗi JSON mô tả cây ảo và props), sau đó truyền về cùng tài liệu HTML ban đầu. Quá trình này giúp mã nguồn của component không bao giờ bị đóng gói vào bundle Javascript client, đem lại lợi thế Zero-Bundle Size [7].

\subsubsection{Streaming với React Suspense và Chunked Transfer Encoding}
Để giải quyết triệt để vấn đề blocking màn hình trắng trong SSR truyền thống, Next.js sử dụng kỹ thuật \textbf{Streaming HTML} thông qua giao thức truyền tải dạng chunked. Trang web được chia tách thành các khối độc lập bọc trong \texttt{<Suspense fallback=\{<Skeleton />\}>}. Máy chủ gửi khung HTML cơ sở và bộ xương Skeleton về cho trình duyệt hiển thị ngay lập tức, sau đó truyền các khối dữ liệu chậm (dàn diễn viên, phim tương tự) về chèn vào vị trí tương ứng khi API phản hồi xong.

\subsubsection{Kiến trúc Caching 4 tầng}
Next.js tích hợp hệ thống bộ nhớ đệm đa tầng gồm: Request Memoization (khử trùng lặp fetch trong 1 lần render), Data Cache (ISR lưu cache dài hạn xuyên suốt nhiều request), Full Route Cache (lưu HTML tĩnh tại build-time), và Router Cache (lưu route trên bộ nhớ client).

Hiệu quả của tầng bộ nhớ đệm Data Cache được tính toán thông qua tỷ lệ truy cập thành công bản đệm (Cache Hit Ratio -- CHR) theo biểu thức toán học (1.1):
\begin{equation}
\text{CHR} = \frac{N_{\text{cache}}}{N_{\text{total}}} \times 100\%
\label{eq:chr}
\end{equation}
Trong biểu thức (1.1), $N_{\text{cache}}$ biểu diễn số lượng yêu cầu được đáp ứng trực tiếp từ bộ nhớ đệm máy chủ, và $N_{\text{total}}$ là tổng số yêu cầu truy vấn tài nguyên. Nhờ áp dụng cơ chế ISR với thời gian lưu 1 giờ trên danh sách phim thịnh hành, tỷ lệ CHR của ứng dụng MovieHub đạt trên 94\% trong các đợt kiểm thử tải.

\begin{lstlisting}[language=TypeScript, caption={Hàm gọi API TMDB tập trung trên Server trong services/tmdb.ts}]
const TMDB_BASE_URL = process.env.TMDB_BASE_URL || "https://api.themoviedb.org/3";
const TMDB_API_KEY = process.env.TMDB_API_KEY;

async function fetchTMDB<T>(endpoint: string, revalidateTime: number = 3600): Promise<T> {
  if (!TMDB_API_KEY || TMDB_API_KEY === "your_actual_api_key_here") {
    throw new Error("TMDB_API_KEY chua duoc cau hinh hop le.");
  }
  const delimiter = endpoint.includes("?") ? "&" : "?";
  const url = `${TMDB_BASE_URL}${endpoint}${delimiter}api_key=${TMDB_API_KEY}&language=vi-VN`;

  const res = await fetch(url, {
    next: { revalidate: revalidateTime }, // Caching ISR
  });

  if (!res.ok) {
    throw new Error(`Loi goi API TMDB [${res.status}]: ${res.statusText}`);
  }
  return res.json() as Promise<T>;
}
\end{lstlisting}

    \item \textbf{Sản phẩm ứng dụng hoàn chỉnh:} Ứng dụng MovieHub hoạt động ổn định, mượt mà, giao diện mang phong cách điện ảnh Netflix Dark Cinema, đáp ứng đầy đủ các tính năng tra cứu, khám phá, xem chi tiết và quản lý danh sách yêu thích thông qua Server Actions và Cookie.

\begin{itemize}[noitemsep]
    \item \textbf{Tư duy phân định ranh giới Server/Client:} Bài học lớn nhất của nhóm là thay đổi hoàn toàn tư duy từ React SPA sang Server-Driven UI [7].     \item \textbf{Kỹ năng làm việc nhóm kỹ nghệ:} Việc tuân thủ quy tắc không commit trực tiếp vào nhánh chính, bắt buộc tạo Pull Request và review chéo đã giúp nhóm phát hiện sớm các lỗi xung đột mã nguồn, nâng cao chất lượng code và kỹ năng phản biện kỹ thuật của từng thành viên.

\end{itemize}
